# Recipe corpus adapter

Optional preparation tools for Musa. The application remains a general document
RAG: recipe parsing stays here and exports ordinary Markdown, JSONL and metadata.
The vector engine, embedding model, chat and active library remain unchanged.

Use the existing project environment; no additional packages are required.
From the repository root, use `.venv\Scripts\python.exe` on Windows or
`.venv/bin/python` on Linux in place of `python` below.

```text
python -m tools.recipes prepare --dry-run
python -m tools.recipes prepare --source huggingface_es --limit 20 --output-dir data/recipe-pilot
python -m tools.recipes prepare
python -m tools.recipes verify --semantic --limit 160
python -m tools.recipes query --country ESP --max-ingredients 4
python -m tools.recipes query --servings 2 --ingredient patata --ingredient huevo
```

`prepare` runs download/discovery, extraction, normalization, validation,
deduplication, export, staging-manifest creation and integrity checks. Progress is
JSON on stdout. An unavailable source is recorded without discarding the others.
Phases also run independently: `discover`, `download`, `extract`, `normalize`,
`validate`, `deduplicate`, `export`, `stage_for_ingestion`, `index`, `verify`, `report`.

Repeat `--source` to select several sources. `--limit` caps records per source
during preparation; for `index`/`verify` it caps the private pilot's document count.
Use a separate output directory for a small pilot to retain full-corpus checkpoints.
`--force` refreshes discovery and derived stages; originals are retained. Thresholds
are configurable with `--title-threshold` (0–100), `--ingredient-threshold` (0–1)
and `--steps-threshold` (0–100). Approximate comparisons use title blocks capped at
200 candidates per record; decisions and skipped-candidate counts are reported.

Default output is **`data/recipe-corpus/`**, ignored by Git:

- `raw/`: pinned originals, notices, URLs and SHA-256 ledgers.
- `extracted/`, `normalized/`, `validated/`: resumable per-source JSONL stages.
- `markdown/`: Spain, international, unconfirmed origin, historical and review groups.
- `rag/recipes.jsonl`: valid deduplicated records with every source attribution.
- `rag/ingestion.jsonl`: the full valid records plus embedding text and Markdown paths.
- `rag/manifest.json`: current exported paths and hashes, including review files.
- `rag/staging.json`: eligible paths; it does not copy files into the active library.
- `rag/catalog.sqlite3`: optional typed filters, separate from the vector store.
- `rag/verification-index/`: private pilot reusing SQLite + NumPy and embeddings on CPU.
- `reports/`: ingestion, license and quality reports, duplicates and verification.

Obsolete Markdown generated by this adapter is moved to `cache/retired-exports/`,
with an audit record. Originals and documents in the active library are preserved.

`index`, `verify --semantic` or `prepare --index` explicitly opt into private-pilot
indexing. They never modify the running library or call a generative model, Ollama
or a cloud provider. The embedding model must already be cached. Retrieval checks
reuse production focused retrieval without its optional reranker. Labels come from
explicit corpus fields, so this is a functional pilot rather than a blind benchmark.
Cases without reference labels remain unevaluable; this does not establish that
the corpus has no answer. The adapter uses the existing loader hook to preserve
`recipe_id`, provenance and typed fields on each chunk. Compatible cases are
exported as `rag/laboratory-pilot.jsonl` for the generic Laboratory.

To import into the application, upload selected eligible Markdown files through
Library and assign a category. Do not upload raw/review folders or copy thousands
of files into the active library without checking capacity. Exact recipe filters
currently belong to this adapter's catalog; the general chat does not interpret
them automatically as SQL over the entire corpus. Unknown or conflicting values
do not satisfy exact filters.

Original fields remain in JSONL and source files. Domestic/historical measures are
not converted to grams; ambiguous ingredient counts remain unknown. Missing titles,
damaged or incomplete records go to review. Historical English adaptations are
retained for review rather than silently translated. Madrid's bilingual PDF uses
a text-layout extractor with physical/printed pages, without vision models.

Licenses are source declarations, not clearance of underlying websites. All source
attributions survive deduplication. The license report identifies unverified rights
and the unspecified OpenRAIL variant. Corpus data and the user's instruction file
are not published with the code.
